## 下载

- SHA256：见附件 `SHA256SUMS.txt`（以本页附件为准）

## 修复：检测"点了没反应 / 一直检测中 / CPU 叠加"

四个独立问题，全部已修：

1. **重复点击会叠加检测**：同一条素材现在只允许一个作业，重复点击直接接上现有进度（`/api/jobs` 可查）；不同素材默认排队（1 路），不再并排抢 CPU
2. **全片解码三遍**：T1（scenedetect）+ RGB + 灰度三次整片解码 → 合并为**单遍解码**，同时产出 T2 的 48×27 RGB 与 T3 的灰度序列
3. **零进度反馈**：作业现在带 `phase / progress / message`，界面显示阶段 + 百分比 + 已用时长，可随时**取消**
4. **状态永久残留**：进程被杀后项目卡在"检测中" → 启动时自动恢复为"上次检测未完成，可重新检测"

附带修复：

- 视频请求不再把整个文件读进内存（始终分块流式），大文件不再爆内存
- 客户端拖动播放导致的连接中断不再刷 `ConnectionResetError` 堆栈（`debug` 级别下只有一行记录）
- ffprobe 调用加超时（probe 60s / 关键帧 300s），网络盘卡住不会无限等待
- 并发写 `project.json` 加锁，避免丢字段

## 新增：控制台分级日志

所有用户行为与任务进度都会打到启动器控制台，并写 `<数据目录>\logs\app.log`（2 MB 轮转 ×3）。

| 级别 | 内容 |
|---|---|
| `debug` | HTTP 请求、帧请求、连接断开 |
| `detail` | 解码进度、候选数、每段导出耗时、5 秒心跳 |
| `info` | 用户行为 + 任务进度（默认） |
| `warning` | torch 缺失降级、作业取消、残留状态恢复 |
| `error` | 检测/导出失败、未捕获异常 |

示例：

```
06:43:42 INFO    [app] scene-cut 0.9.2 启动（日志级别=detail，数据目录=...）
06:43:42 INFO    [env] torch 2.0.1+cpu cuda=False threads=8
06:43:44 INFO    [detect] 开始 素材=demo.mp4 帧=510 fps=30 1280x720
06:43:45 INFO    [detect] t1 完成 762ms 候选=1
06:43:47 INFO    [detect] 解码 完成 2283ms 帧=510 灰度=320x180
06:43:53 INFO    [detect] t2 完成 4106ms device=cpu
06:43:53 INFO    [detect] 完成 3 镜头 用时 7207ms
```

修改级别（四选一，即时生效）：

- 命令行：`scene-cut.exe --log-level detail`
- 环境变量：`set SCENECUT_LOG_LEVEL=debug`
- 配置文件：`<数据目录>\settings.json` → `{"log_level": "detail"}`
- 界面底部状态栏「日志」下拉框

> 排障建议：检测异常时切到 `detail` 重跑，控制台会显示卡在哪个阶段（probe / t1 / decode / t2 / fuse）。

## 使用

1. 解压到任意目录（**不要**放进 `Program Files`）
2. 双击 `scene-cut.exe`：启动本地服务 + 独立应用窗口（最小 1200×780，关窗即退出）
3. 需要系统 `PATH` 中有 `ffmpeg` / `ffprobe`，或放到 `_internal\_bin\`

## 说明

- 数据默认写入 `%LOCALAPPDATA%\SceneCut`（可用 `SCENECUT_DATA` 指定）
- 窗口依赖系统 WebView2 运行时（Win10/11 默认自带）
- exe 未签名，首次运行会有 SmartScreen 提示，选“仍要运行”
- 本包不含 ffmpeg；随包分发请用 LGPL 构建（`tools/fetch_ffmpeg_lgpl.py`）
